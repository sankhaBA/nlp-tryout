## Approach: LLM-synthesized data

The dataset is **not** hand-written or rule-templated. It is generated by prompting **Google
Gemini** (model id `gemini-3-flash-preview`) with a strict instruction prompt, once per
*scenario*. Each call asks the model to produce **50 unique** `input,target` rows that all fit
one navigation situation. With 125 scenarios this targets ~6,250 raw rows before
de-duplication and curation.

```
scenarios.json[i]  ──┐
                     ├─►  master_prompt.replace("[INSERT SCENARIO]", scenario)  ──► Gemini ──► 50 CSV rows
master_prompt.txt  ──┘                                                                │
                                                                                       ▼
                                                              append to indoor_navigation_dataset.csv
```

## The generation script

[dataset_generator.py](../dataset_generator/dataset_generator.py) flow:

1. **Load `.env`** from the project root and the script dir via a small hand-rolled parser
   (`load_env_file`), reading `GEMINI_API_KEY`. Missing key → hard error.
2. **Configure Gemini**: `genai.configure(api_key=…)` and
   `model = genai.GenerativeModel('gemini-3-flash-preview')`.
3. **Load inputs**: `master_prompt.txt` (validated non-empty) and `scenarios.json`
   (validated to be a non-empty JSON array of non-empty strings).
4. **Resume logic** (`get_start_scenario_index_from_metadata`):
   - If `indoor_navigation_dataset_metadata.json` exists, resume from its
     `last_successful_scenario_index`.
   - Otherwise fall back to the module constant `LAST_SCENARIO_INDEX = 63`.
   - The CSV header `input,target` is written **only** when starting from index 0; otherwise
     the script **appends** so prior work is preserved.
5. **Per-scenario loop** (`scenarios[start:]`):
   - Inject the scenario into the prompt (`replace("[INSERT SCENARIO]", scenario)`).
   - Call `model.generate_content(prompt)`.
   - **Clean the response**: strip ` ```csv ` / ` ``` ` fences; drop a leading `input,target`
     header line if the model re-emitted it; skip blank lines.
   - Append the cleaned rows to `indoor_navigation_dataset.csv`.
   - Write progress to metadata with `status: "running"`.
   - **`time.sleep(45)`** between calls to stay under API rate limits.
   - On any exception: write metadata with `status: "stopped_on_error"`, capture the failed
     scenario index/text and the error message, then `break`.
6. On clean completion: write metadata with `status: "completed"`.

### Run it

```bash
# from the repo root, with GEMINI_API_KEY set in .env
python dataset_generator/dataset_generator.py
# → writes dataset_generator/indoor_navigation_dataset.csv
#   and dataset_generator/indoor_navigation_dataset_metadata.json
```

## The master prompt (output contract)

[master_prompt.txt](../dataset_generator/master_prompt.txt) defines the dataset rules. The model
is told it is an **expert dataset generator** producing **50 unique** rows for a seq2seq model
that helps **visually-impaired** users navigate a mall. Key constraints (verbatim intent):

- **Strictly action-oriented** — the user cannot see. Do **not** describe the environment,
  shops passed, glass doors, textures, or incidental landmarks.
- **"Only When Necessary" landmark rule** — include a landmark *only* if it is either:
  1. the **final destination** (e.g. "washroom", "Zara"), or
  2. a **floor-changing mechanism** the user must interact with (elevator, escalator, stairs).
- **Distances are exclusively in steps** (e.g. "15 steps") — never metres.
- **Output is raw CSV** — no intro/outro text, no markdown fences, two columns exactly
  (`input`, `target`); `target` wrapped in double quotes.
- **Input column format:**
  `action: [continue/turn/stop/board/exit] direction: [left/right/straight/up/down — if applicable] distance: [X steps — if applicable] landmark: [destination or floor-changer — ONLY if applicable]`
- **Target column format:** the minimal, natural spoken-English instruction.

The prompt ends with six **few-shot examples** so the model anchors on format and tone, e.g.:

```
action: continue distance: 40 steps,"Continue straight for 40 steps."
action: stop landmark: pharmacy,"Stop here. You have reached the pharmacy."
action: board direction: up landmark: escalator,"Step onto the escalator going up."
```

> The exact `input` grammar produced here is the contract the model later learns and that the
> on-device app must emit. It is documented in full in [02-dataset-and-schema.md](02-dataset-and-schema.md).

## Scenarios

[scenarios.json](../dataset_generator/scenarios.json) is a flat JSON array of **125** plain-English
scenario descriptions. They are intentionally *granular* navigation situations rather than
high-level tasks, and span:

- straight walks (short and very long — 70 to 150 steps), L-shaped/zig-zag/U-turn paths;
- turns at T-junctions, alternating turns, loops;
- elevator board / ride / exit sequences across floors;
- escalator (ascending/descending) board and step-off sequences;
- staircase climb/descend, emergency-exit stairs, service elevators;
- destination stops (named shops, restrooms, ATM, info kiosk, food court, etc.).

Example entries:

```json
"Walking straight from the main entrance lobby deep into the ground floor.",
"Entering an elevator and pressing the button for the 3rd floor.",
"Stepping off an ascending escalator and walking straight for 20 steps.",
"Walking to the emergency exit stairs and descending one flight down."
```

## Validation: duplicate detection

[dataset_validator.py](../dataset_generator/dataset_validator.py) is a standalone CLI that reports
exact-duplicate `(input, target)` pairs — LLM generation naturally repeats near-identical rows.

```bash
python dataset_generator/dataset_validator.py --file data/nav_dataset_b4.3.csv
```

It prints total rows, unique rows, count of duplicated lines, total duplicate instances, and a
sorted listing of each duplicated row with its frequency. (Note: the *training* notebook also
de-duplicates with `df.drop_duplicates` — see [03-model-training.md](03-model-training.md).)

## Checkpoint / error log

[indoor_navigation_dataset_metadata.json](../dataset_generator/indoor_navigation_dataset_metadata.json)
is rewritten after every scenario. Its schema:

| Field | Meaning |
|-------|---------|
| `dataset_file` | output CSV name |
| `last_successful_scenario_index` | 1-based index of last completed scenario (resume point) |
| `last_successful_scenario_text` | text of that scenario |
| `status` | `running` \| `completed` \| `stopped_on_error` |
| `failed_scenario_index` / `failed_scenario_text` | present only on error |
| `error_message` | the raw exception text |

The committed metadata records a real run that **stopped at scenario 67** because the Gemini
**free tier** quota was hit (`429 … limit: 20 … GenerateRequestsPerDayPerProjectPerModel-FreeTier`).
This is the practical reason generation was done in **batches** over multiple days, producing the
`data/nav_dataset_b*.csv` version history.

[.env](../.env) currently contains a **real, live `GEMINI_API_KEY`**. Although `.env` is listed
in [.gitignore](../.gitignore), the value exists in the working tree. If this key has ever been
